# 架构说明

## 一句话

**三层能力（Tier 0 / Tier 1 / 原生层）+ 一个权威来源（`SKILL.md`）+ 一套会被证明会失败的门禁。**

## 三层能力

| 层 | 位置 | 依赖 | 为什么必须单独成层 |
|---|---|---|---|
| **Tier 0** | `scripts/` | **纯标准库** | Claude Code / Codex 自带的 Python 常常没有 numpy。分析的入口必须能跑起来 |
| **Tier 1** | `vendor/` + `lib/` | numpy + pandas (+ scipy) | 统计、建模、组学算法 |
| **原生层** | `vendor/native/` | 无（单文件可执行） | 百万行级流式质控，Python 太慢（3M 行 551 ms vs 约 6 s） |

**降级规则**：Tier 1 的 22 个模块是**逐个探测可导入性**的
（`scripts/capabilities.py::_probe_lib_modules`）。缺一个依赖，只有那一个模块标为
不可用，**不影响其余**。

> 这是刻意设计。用一次 `try/except` 包住整层，会把「A 模块缺依赖」
> 误报成「所有分析法都没有」——这类误报会直接误导调用方去重复造轮子。

## 数据流

```
用户提问
   │
   ├─ SKILL.md 的 description 命中 → 自动加载（无需手动点）
   │
   ├─ 路由决策树：想法 / 数据 / 审计 / 产出 / 药物
   │
   ├─ 查「分析法总表」→ 选方法 + **先确认口径**
   │
   ├─ 调 lib/ 或 scripts/ 的确定性函数（AI 不参与计算）
   │
   └─ 结果必须带：数值 + 口径 + engine + 中间诊断量
```

**AI 不参与计算**：所有数字由脚本算出。AI 负责的是「选哪个方法」「口径对不对」
「这个结论能不能从这些数里推出来」——而不是「这个数大概是多少」。

## 为什么 `SKILL.md` 是唯一权威

`AGENTS.md` / `GEMINI.md` / `.cursor/rules/*.mdc` / `.clinerules/*` 等入口
**全部由 `scripts/install_adapters.py` 生成**，不手写。

手写多份入口 = 迟早漂移。（设计文档附录 B 陷阱 #21：
同一逻辑多处实现 → 同一句话在不同模块得到不同结论。）

## 门禁设计

| 门禁 | 位置 | 保护什么 |
|---|---|---|
| 全量自检 | `tests/run_all.py` | 功能 / 稳定 / 安全 / vendor / 分析法 / 原生层 |
| **门禁负向用例** | `tests/test_guards_negative.py` | 证明门禁**会失败**（构造退化检测器） |
| 自动触发覆盖 | `scripts/trigger_check.py` | `description` 的触发词是否覆盖新能力 |
| 双层能力探测 | `scripts/capabilities.py` | 本机哪层可用（**逐模块**） |
| 幂等门禁 | `tests/test_vendor.py` | 同步头不得含随环境漂移的东西（日期 / 路径） |

> 「门禁必须被证明会失败才算有效」——`test_guards_negative.py` 专门构造
> 恒定输出型、语义反转型的退化检测器，断言门禁会 FAIL。
> 一个「0 失败」如果来自门禁是摆设，那比没有门禁更危险。

## 关键设计约束（每一条都是踩出来的）

1. **同一逻辑只允许一个裁决点**。例：MAF 折算的唯一裁决点是
   `scripts/_common.py::as_maf`；原生层的 `sumstats` 必须与它同口径。
2. **参与幂等比对的字符串不得含随环境漂移的东西**（日期、路径、PID）。
   实例：同步头曾写 `# 同步日期: <today>` → 跨天即脏，幂等门禁**每天必然假失败一次**。
   改用**源文件 sha256**（由内容决定）。
3. **报告类指标的计算顺序不能自己抹掉它要暴露的问题**。
   实例：VIF 必须在相关剪枝**前**算——先剪枝再算必然接近 1（实测 r=0.998 的两列
   剪枝后 max_vif=1.019，看着完全正常）。
4. **兜底透传入口必须绕开自己的参数校验**（放在 `--input`/argparse 前置校验之前），
   否则兜底入口形同虚设。
5. **vendored 之后必须做导入相对化**。原包的绝对导入（`from pymr.methods import`）
   在 vendored 后失效，且**运行到那一行才抛** `ModuleNotFoundError`——
   「能用一半」的隐性失败比直接报错更危险。

## 目录职责

| 目录 | 职责 |
|---|---|
| `SKILL.md` | 唯一权威：路由 · 红线 · 判定门 · 37 个分析法总表 |
| `scripts/` | Tier 0 执行层（纯标准库）+ 跨 agent 安装器 |
| `lib/` | 本仓库自有扩展（22 个模块，包装 vendor 或独立实现） |
| `vendor/` | 内嵌工具层（同步件 + 移植件 + 原生二进制），来源见 `ATTRIBUTION.md` |
| `references/` | 知识层，按需加载，零常驻成本 |
| `pipeline/` | 确定性分析管道（配置驱动，AI 不碰数值） |
| `tools/` | `vendor_sync` / `fetch_tools` / `wrapper_core` / `native_accel` |
| `docs/` | 本目录：架构与设计说明 |
| `tests/` | 自检层 |
